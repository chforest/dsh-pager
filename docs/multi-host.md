# 一台手机，多台电脑

一个 App 可以保存多台电脑的地址，每台各跑一个 `dsh web`。它们互不干扰：
各自的登录 cookie、各自的通知游标、各自的工作区。

## 先装哪个包

这个分支的安卓包是**独立的 App**：包名 `com.agenthub.dshmulti`，桌面名称「DSH 多机」，
图标是把原来的靛蓝提示符换成了青绿的两台机器。它可以和原来的 DSH 同时装着，互不影响
（各自的设置、登录 cookie、通知都是分开的）。

## 预设第一台

自己用的构建可以在 `android/local.properties`（git 忽略）里写死第一台的地址，
装好就直接进它，连首屏都不用填：

```
DSH_DEFAULT_SERVER=http://47.97.159.150:3080
```

构建时 `build.sh` 会把它写进 `default_server`，首次启动时自动变成列表里的第一条
（所以通知、切换都正常）。源码里的默认值保持为空，公开发布的包仍然会先问地址。

## 怎么加

在 App 里点「切换服务器」（或首次启动时的连接页）会打开「已保存的电脑」：

1. 填地址（`https://dsh.example.com:8443`、`http://100.x.y.z:8080` 都行）；
2. 备注可选，写了就显示成「工作室」「家里」这种名字，没写就显示地址；
3. 点「保存并连接」。

再想加第二台，回到这个页面继续填。列表里点「连接」切换，点「删除」移除（同时清掉它在后台的提醒连接）。

第一次进入每台电脑时都要各自登录一次：粘贴那台 `dsh web` 打印的 `?token=` 链接（见
[绑定地址、登录与排查](host-binding-and-signin.md)）。cookie 是按域名分开存的，切换不会把另一台挤掉。

## 它是怎么工作的

- 前台只显示一台：WebView 当前打开的那个 origin。
- 后台**每台各一条** `/m/api/notify` 长连接（`NotifyService` 里 `reconcile()` 维护），
  所以 A 机上的任务完成时，即使你正在看 B 机，也会收到提醒。
- 通知标题在多台时会带上主机名（「工作室 · …」），点开或直接回复都会回到**产生这条通知的那台**，
  不会串到当前正在看的电脑上。
- 通知游标（`epoch` / `n`）和 cookie 存在 `h.<origin>.*` 下，各机独立；旧版本的单机配置在
  第一次读取时会自动迁移成一条记录。

## 已知边界

| 事项 | 现状 |
|---|---|
| 会话列表 | 一次只看一台。首页是当前这台电脑的会话，不做跨机合并 |
| 会话续接 | 不行。DSH 的会话存在各自的进程里，同一条任务换台电脑接不上 |
| iPhone / 网页版 | 仍然是「一个地址一个主屏图标」；多台就是多个图标，各自可以单独开 Web Push |
| 桌面小组件 | 显示最近一条状态，多台时可能在不同主机之间跳动 |

## 和「网关聚合」的区别

如果你的机器比较多（5 台以上），或者希望手机上永远只看到一个入口，可以改成在
一台机器上做聚合网关：由它去连其他 DSH，手机只连它。代价是那台机器要长期持有其他机器的凭据，
权限面更大，所以这个 App 走的是「客户端多连」而不是「服务端聚合」。
