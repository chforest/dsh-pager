# 更新与意外重启后的恢复

`recovery-host` 记录启用后观察到的普通聊天断点，并与自动任务服务共享启动判定。它不修改原聊天日志，不替换模型，不增加工具权限。

用户批准更新或重启后，DSH 可调用 `dsh_prepare_restart` 保存十分钟有效的重启意图；工具本身不执行更新。意外进程退出，或携带有效意图的重启后，插件加载原聊天核对断点。干净退出但没有重启意图、同进程热更新，都不自动恢复。

普通聊天只有原话轮未完成、没有新的用户输入、手动停止、目标暂停或待审批等阻碍时，才派发一次恢复核对提示。先确认最后工具调用的实际产物和独立回执，未知结果不能直接重放；发送、发布、付款仍受原授权范围约束。恢复提示自身派发结果未知时也不重复发送。

计划任务由调度服务单独恢复，避免双重派发。判断基于当前话轮或运行归属；历史上运行过计划不会永久禁止后来普通聊天恢复。连续目标仅在原目标和剩余预算内恢复；不完整单次任务保持待核对。

## 安装与存储

先加载 recovery-host，再加载 tasks-host。默认状态文件为 `$DSH_HOME/extensions/recovery/recovery.json`，任务索引为 `$DSH_HOME/extensions/tasks/tasks.json`；DSH_HOME 未设置时使用 `~/.dsh`。可通过 `stateFile`、`tasksFile` 显式指定现有文件。检测到旧文件却未配置时停止初始化，不自动搬迁或合并。

迁移须停用插件、备份并保留完整日志，包括未知派发屏障。不要为了恢复任务手改标记或清空状态。运行数据、实际会话标识和日志不上传公开仓库。

## 限制与测试

首次启用前已经中断的工作不会凭猜测恢复。原生目标由其驱动器处理，普通恢复不强行恢复暂停目标。用户取消尚未持久化便发生断电，以及磁盘故障导致检查点无法保存，属于无法保证完整识别的窗口；恢复时仍须核对历史和产物。

高频流式事件不写恢复日志。存储异常会禁止本轮自动恢复，而不把异常抛回业务事件循环。测试覆盖人工停止、晚到输入、审批、重复派发、热更新及存储错误；缺少 DSH SDK 的 CI 明确跳过真实 SDK 集成项，纯测试继续执行。
