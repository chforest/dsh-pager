# 绑定地址、登录与「点不动」的排查

这篇讲三件在 DSH 0.2.1 之后才出现、但很容易踩的事：

1. `dsh web --host` 换了绑定地址之后，手机上的提问卡片点不动；
2. DSH 自带登录之后，手机 App 没有地址栏，怎么把 token 交给它；
3. 出现红字时，哪一句是真话、哪一句是旧版本的误报。

## 1. 绑定地址不是回环时

DSH 的监听地址由 `--host` 决定，而且**只绑那一个地址**：

```bash
pnpm dsh web --no-open --host 10.181.64.56 --port 3080 \
  --trusted-host 47.97.159.150 --public-url http://47.97.159.150:3080
```

这样启动后，`10.181.64.56:3080` 通，`127.0.0.1:3080` **是不通的**。插件早期版本把内部调用（把手机上的回答交回 DSH）写死成 `127.0.0.1`，于是：

- 手机能看会话、能发消息（走的是进程内 RPC）；
- 但一提交审批或提问的回答，内部那次 POST 就连不上，插件把异常兜成 502，手机显示「家里电脑暂时连不上」；
- 这道题在 DSH 那边其实还挂着，所以你点多少次都是同一个错。

现在的做法是跟随 `ctx.webServer.host`。自己确认一下当前进程绑在哪：

```bash
# 3080 的十六进制是 0C08
awk 'NR>1 {split($2,a,":"); if (a[2]=="0C08") print $2}' /proc/net/tcp
# 10.181.64.56 会显示成 3840B50A（小端）
```

如果只有一行、而且不是 `0100007F`（127.0.0.1），就说明回环没监听——这正是需要本修复的场景。

## 2. 登录：token 每次重启都变

DSH 0.2.x 起，`dsh web` 启动时会打印一条带 `?token=` 的链接。打开它，DSH 会种一个 **30 天有效**的 cookie，之后访问 `/m/` 就不用再带 token。

- token 本身是**每次进程启动现生成的**（32 字节随机），没有配置项，重启必变；
- cookie 的签名密钥存在 `~/.dsh/.credentials.yaml`（`client-connection/browser-session`），**重启不会失效**。

所以「每次都要重新登录」通常不是 token 变了，而是 cookie 没保住：换过服务器地址、清过 App 数据、或者 WebView 把 cookie 丢了。

### 安卓 App 没有地址栏怎么办

直接打开 `/m/login`，把终端里那条链接整段粘贴进去（也可以只粘 token）：

```
http://47.97.159.150:3080/m/login
```

页面会把 token 转发给 DSH 自己的 `/?token=…` 兑换 cookie，成功后进入 `/m/`。未登录时访问 `/m/` 也会自动跳到这里，所以正常流程里你不需要记这个地址。

## 3. 红字对照表

| 手机上的提示 | 实际含义 | 处理 |
|---|---|---|
| 家里电脑暂时连不上 | 内部请求拿到 502/503/504：要么进程连不上自己，要么 DSH 拒绝了这次回答 | 先确认第 1 节的绑定地址；升级到本 fork 的版本后会显示真实原因 |
| 问题已失效或已提交 | 这道题在 DSH 那边已经结束（超时、已答、回合被打断） | 正常现象，卡片会被自动收起；需要的话让 DSH 重新问一次 |
| 卡片点了没反应 | 旧版本提交后不清理卡片，或请求挂在半死的连接上 | 本 fork 已修：提交即收起卡片，失败静默重试一次，仍失败才还原并保留所选 |

DSH 的 `ask_user_question` 默认只等 **120 秒**。超时后题目在主机侧就结束了，手机上的卡片却还在——如果你隔几分钟才点，看到的就是「问题已失效」。想答得从容一点，就在提问时把 `timeout` 调大（或设成 `-1` 一直等）。

## 4. 关于通知

不需要额外配置，规则在 `plugin/notify.js`：

- 回合完成 → `done`（时长 ≥ 10 秒，或这条提问是从手机发出的）；
- 失败 / 中断类结局 → `error`；
- 有待审批、待回答 → `ask` / `q`，每次手机重连都会重发未处理的那条；
- 子 agent 的中间回合不推送。

安卓靠 App 常驻的通知服务；iPhone 用 Web Push，需要在 `/m` 的设置里开启一次（服务端会把订阅存在 `~/.dsh-pager/`）。收不到提醒时先检查系统层面的三件事：允许通知、电池策略设为「无限制」、允许自启动。

## 5. 验证清单

重启 `dsh web` 之后，按顺序确认：

```bash
# 1. 绑定地址通、回环不一定通
curl -sS -o /dev/null -w '%{http_code}\n' http://<绑定地址>:3080/m/

# 2. 登录页可达（未登录时会返回登录页而不是 403）
curl -sS -o /dev/null -w '%{http_code}\n' http://<绑定地址>:3080/m/login

# 3. 手机：发一句话，让 DSH 提一个问题，点选后提交
#    预期：卡片立刻消失，不再弹红字
```
