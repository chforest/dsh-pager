# 电脑端文件查看

## 文件右键菜单

Windows 与 macOS 本机 DSH 的“文件”页和聊天中的原生生成文件入口可用右键或 Shift+F10 打开同一菜单：打开文件、用 VS Code 打开、打开方式、另存为、复制路径、复制文件内容、在资源管理器 / Finder 中定位。Esc 或点击菜单外关闭；切会话取消旧请求。

默认打开视频仍使用已配置的播放器；其他受支持文档/图片使用系统关联（Windows Explorer / macOS `open`）。VS Code 可通过 `codePath` 或 `DSH_VSCODE_PATH` 配置（macOS 亦支持 `/Applications/Visual Studio Code.app`），不安装编辑器。另存为使用系统保存窗口（Windows SaveFileDialog / macOS `osascript` `choose file name`）及覆盖确认，完成后显示实际目标路径。目录不能另存为或复制内容，二进制或超过预览上限的文本不提供“复制文件内容”，避免误复制截断数据。

原生操作必须来自本机同源桌面，服务器重新核对当前会话工作区及真实路径。可执行文件/快捷方式不作为普通文档执行；脚本可在 VS Code 中查看。系统接受打开请求不等于第三方应用已成功显示文件，失败或未知结果不自动重试。

新增接口 `/m/api/desktop/file-action` 仅接受固定动作枚举和会话/路径；路径通过环境变量或 stdin JSON 传给固定系统助手，不拼接命令字符串。手机与平板原有文件浏览方式保持不变。

在 DSH 对话中选择“文件”页签。点击文件夹进入，用“上一级”或工作区根目录返回；文件行和当前位置旁的复制按钮复制服务端校验后的完整路径。

图片、音频和文本支持页内预览，不自动播放媒体；关闭预览返回目录。无法内嵌展示的文件会明确提示，仍可复制路径。切换聊天或目录会取消旧请求，避免显示上一会话内容。

Windows 与 macOS 本机点击视频文件名时，请求本机播放器打开，另有“页内预览”选项。该行为不修改系统文件关联。启动回执仅表示播放器进程已接受启动，不等同于视频已解码或播放成功。

## 安装配置

启用 `files-host` 并保留同仓库 `plugin` 文件接口；前端以可解析的包名注册，作为原生 conversation.view 页签出现，不替换聊天界面。

播放器路径优先使用 `config.playerPath`，其次 `DSH_VIDEO_PLAYER_PATH`。Windows 默认还会尝试 `%ProgramFiles%/ai-player/AgentPlay/AgentPlay.exe`；macOS 默认按顺序尝试已安装的 `IINA.app`、`QuickTime Player.app` 或系统 `open`。第三方播放器不随插件分发，安装来源与许可证须另行确认。

## 访问边界

目录、链接和敏感文件检查由工作区文件接口统一执行。原生视频打开额外要求 Windows 或 macOS 本机来源、根聊天页面及已校验的视频文件，仅以参数数组启动指定程序，禁用 shell，不允许客户端指定可执行文件。

不要公开真实工作区文件、截图、配置或日志。自动化测试使用虚构路径和模拟进程；实际播放器、剪贴板和不同屏幕布局仍需平台验收。
