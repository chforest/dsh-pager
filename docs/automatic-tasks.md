# 自动任务

电脑端在对话的“任务”页签管理计划；手机和平板从对话菜单进入自动任务。模型可使用 `automatic_tasks_list` 和 `automatic_tasks_manage`，与页面共用同一持久化台账。创建成功须以返回的任务 ID、状态和下次执行时间为准，写入说明文档不等于创建计划。

## 执行与上下文

有来源聊天时，在原聊天中执行，使用其现有上下文、当前模型和权限，不重命名或覆盖设置。没有来源聊天的独立任务只在首次建立执行聊天，以后复用。原聊天忙、有未完成目标、待审批或待处理消息时等待，不另开聊天抢跑。

工具创建沿用当前会话权限，不允许自动提升。独立页面创建采用服务提供的权限选项；审批和外部操作授权不会自动同意。单次任务执行一轮；连续任务由原生目标机制在配置的轮数预算内推进。到达预算、受阻或状态未知时不能宣称完成。

支持立即、指定时间、延时、间隔、每天及每周；时间显示为北京时间，间隔至少五分钟。同任务不重入，共享聊天互斥，默认并发上限为二。错过多轮周期合并处理，不堆积补跑。后台服务必须运行，关闭页面本身不会暂停计划。

## 重启与结果

意外重启或已准备更新意图的重启后，调度器核对原运行记录。仅已确认派发、原目标 ID 一致、目标可恢复且还有预算的连续任务可以恢复；不重建目标、不增加预算。用户暂停、归档、新输入、待审批及未知工具结果会阻止自动续发。单次任务中断且结果未确认时，保留待核对状态，不自动重放。详见 [恢复机制](recovery.md)。

结果根据本次运行标记、目标 ID 和话轮边界关联，不能把旧总结或后来的用户工作当成本次结果。派发未知时先查询台账和独立回执，不能盲目重试。

## 安装与数据

按仓库安装配方启用 `tasks-host`，并保留 `plugin`、共享任务页面及官方 DSH SDK 依赖。需要恢复能力时先加载 `recovery-host`。前端插件应以可解析的包名注册，不能把绝对文件入口误当成前端包名。

新默认数据目录是 `$DSH_HOME/extensions/tasks`，未设置 DSH_HOME 时是 `~/.dsh/extensions/tasks`。`config.dataDir` 优先；发现旧存储且未指定路径时停止初始化，避免静默创建空台账。迁移前暂停任务、停用插件、备份并复制完整存储，更新配置后先只读核对，再按用户意图启用。不得合并不同台账或删除未知派发记录。

任务内容、运行数据、会话标识、回执和日志不属于公开源码。测试使用合成数据，不代表真实业务已经执行成功。
